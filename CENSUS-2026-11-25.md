# Census — what exists, and where the site actually reads from

Written before any change. Every number here was measured, not estimated.

---

## The critical fact I had wrong

The live worker runs `DB_PROVIDER_MODE=turso_full`. **The site reads Turso, not D1.**

Everything I scraped and loaded overnight went into **D1**, which the site never
queries for the main screens. That work is not lost — it is in the wrong database.

| Database | Role | Site reads it? |
|---|---|---|
| **Turso `horse-registry-canonical-20261122`** | LIVE canonical since 2026-11-22 | **YES** |
| D1 `f527d88f-…` | old provider, still bound as `DB` | No |

## Turso quota — currently drained

Direct probe of the canonical DB returns:

```
BLOCKED: SQL read operations are forbidden
         (reads are blocked, do you need to upgrade your plan?)
```

Organization usage for this billing period:

```
rows read     7,254,569,340
starter quota   500,000,000      -> 14.5x over
rows written      4,575,732
starter quota    10,000,000      -> 46% used, NOT blocked
```

`blocked_reads: true`, `blocked_writes: false`.

**The site is serving right now** — health, horse list and horse detail all
return 200 — because the worker has a response cache. Once that cache expires
for a given query it will have nothing to fall back on.

## Why reads are so high

The worker runs, for every horse detail request, an unbounded aggregate:

```sql
FROM racing_results WHERE registry_horse_id=?
```

`registry_horse_id` has **no index** on Turso (13 indexes exist, not that one).
Each request is therefore a full scan of `racing_results`. A handful of page
views burn the entire monthly allowance.

## The decision that has to be made

The site is one cache expiry away from being an empty shell until the Turso
billing period resets. Two ways out:

1. **Wait for the Turso monthly reset.** Zero cost. The site may degrade to
   errors before it arrives.
2. **Point the worker back at D1** (`DB_PROVIDER_MODE=d1_full`). D1's read
   quota resets **daily** and has 5M rows/day. But D1 is missing the
   post-2026-11-22 changes made directly in Turso, so this is a rollback in
   data terms and needs a diff first.

This is a product decision, not a technical one, so it is written here for a
human to choose. Everything that can be done safely without that decision is
being done first.
