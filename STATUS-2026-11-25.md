## Why it took three attempts

**Attempt 1** used `OFFSET` pagination on a 95,652-row table. Each page
re-scans everything it skips, so the first page cost a page's worth of rows
and the second cost two pages' worth. The daily 5M row-read budget was gone
before the table was read.

**Attempt 2** fixed the pagination but hung for six minutes. The cause was
worse: my row arrays were **38 values wide against a 41-column table**. Every
batch failed validation instantly, and the error path fell back to inserting
row by row — 17,659 individual requests. It was still grinding when I killed it.

**Attempt 3** works, because it was built on measured limits rather than
guesses:

| Limit | Measured value |
|---|---|
| Rows per day (reads) | 5,000,000 |
| Rows per day (writes) | 100,000 — and writes cost **zero** reads |
| Max SQL statement | ~100 KB. 200 wide rows (70 KB) passes; 400 (139 KB) fails `SQLITE_TOOBIG` |
| Cheap `SELECT 1` | **lies.** Served from cache while real reads are capped |

The final loader packs rows by *byte size*, not row count, and halves its
target when it hits `TOOBIG` instead of skipping data.

## One more bug worth recording

The first version of the crosswalk matched only **19.6%** of results to
registry horses. The cause was a single line:

```python
s.replace('\u064a', 'i').replace('\u0643', 'k')   # wrong
```

That maps **Arabic** yeh and kaf to *Latin* letters. The registry stores names
in Arabic script (`ي` `ك`), asbdavani writes them in Persian script (`ی` `ک`),
so the two could never meet. Confirmed against the live API:

```
/api/horses?limit=2  ->  name_native: "\xda\x86\xd8\xa7\xd8\xa8\xd9\x83"  = چابك
```

Correct fold (`أإآ→ا`, `ي ى→ی`, `ك→ک`, `ة→ه`) plus birth-year/race-year
disambiguation lifted the match rate:

| Table | Before | After |
|---|---|---|
| racing_results_archive | 3,459 — 19.6% | **9,766 — 55.3%** |
| horse_profiles_archive | 1,219 — 28.7% | **3,291 — 77.4%** |
| asb_doping_verdicts | 23 — 19.3% | **79 — 66.4%** |

The remaining ~45% of results are horses that are genuinely absent from the
registry, or share a name with several horses and have no usable birth year.
Those rows are stored with `registry_horse_id` NULL rather than guessed.
